Approach 1 Production Ready

Multi-Organization Architecture Implementation Report

Engineering documentation for Single GitHub App & Private Key multi-organization governance auditing.

1. Architectural Overview

In enterprise environments across GitHub Enterprise Cloud (GHEC), GHE.com (Data Residency), and GitHub Enterprise Server (GHES), enterprises frequently segment business units into separate GitHub Organizations (e.g., DefaultOrg24, PaymentsCore, IdentityPlatform).

Prior to this implementation, Repo360 bound its authentication token state to a single installation ID. Auditing multiple organizations required distinct credentials or multiple runs.

With Approach 1, a single GitHub App identity (1 app_id and 1 private_key) is registered once and installed across $N$ organizations. Repo360 dynamically negotiates and caches installation tokens per organization, allowing one unified audit run across all installed organizations or any targeted subset.

Dimension Legacy State (Single Org) Implemented Multi-Org Architecture
App Credentials 1 App ID, 1 Private Key, 1 Static Installation ID 1 App ID, 1 Private Key, Dynamic multi-installation resolution
Token Caching Single global token variable Per-installation cache (Dict[int, Tuple[str, float]])
API Request Routing Static token header across all requests Dynamic path-based extraction (/orgs/{org}, /repos/{org}/{repo})
Discovery Single installation only Paginated discovery across all installations; selective --org filtering
Reporting Single organization context Aggregated metrics across all audited organizations

B. API Client Request Brokerage (src/collector/client.py)

Added automatic path-based organization extraction. When requests target /orgs/{org}/... or /repos/{org}/{repo}/..., GHECClient automatically injects the corresponding organization's bearer token without requiring checks to manually manage headers.

Before (Static Header Injection)
for attempt in range(1, self.max_retries + 1):
    headers = self.auth.get_auth_headers()
    response = self.session.get(url, headers=headers)
After (Dynamic Path-Based Org Token Switching)
target_org = org or self._extract_org_from_path(url)
for attempt in range(1, self.max_retries + 1):
    headers = self.auth.get_auth_headers(
        installation_id=installation_id,
        org=target_org,
    )
    response = self.session.get(url, headers=headers)

D. CLI Orchestration & Filtering (src/main.py)

Introduced the --org CLI argument on repo360 audit. If omitted, the audit auto-discovers all installations across the enterprise. If specified (e.g. --org OrgAlpha,OrgBeta), it audits only the requested organizations.
